# 翻牌显示 Split-Flap · 任务书

短名 `split-flap` · 分支 `claude/film-split-flap` · 建议 112.5 BPM（一拍 32 帧，一张牌翻 4 帧 = 三十二分音符）

**第 0 帧**：一整面翻牌墙占满画面（约 60 × 26 块，哑光黑牌），**一道斜的波正扫到画面中间**——波扫过的左半边已经落定成信号黄的巨大像素字「翻牌」，波前上的几百块牌正翻到一半（各种角度、带运动模糊、牌面反着顶光），波还没到的右半边是上一幅画面的残留。一眼看到：大字、黄黑对比、一条正在动的线。

**只属于它的物理**：
1. **要到 Z，必须翻过 A—Y。** 每块牌是一叠按固定顺序排的卡片，只能往前翻。所以“到站时间 = 起跑时间 + 要翻的张数 × 一张的时间”。整面墙的波浪、涟漪、最后零星几块还在翻——都是这条规则算出来的，不是一块块 K 的。
2. **牌是掉下来的，不是转过去的。** 角度按重力加速（先慢后快，`θ ∝ t²`），撞到挡片停住，回弹一下（约 4%、2 帧）。掉的过程中它的影子压在下半张上。
3. 每张牌落定一声“嗒”。几百声叠成一阵雨，最后一块落定是单独的一声。

**接力**：从头到尾同一面墙、同一批牌，画面内容全靠翻。镜头从整面墙**连续推到一块牌跟前**（看清一张牌怎么掉：铰链、卡片厚度、影子、上半张 + 下半张中间那条缝），再连续拉回去。

**可以演的东西**（顺序、取舍自己定，不必都用）：整面墙当点阵屏放一段动画（弹跳的球 / 心跳 / 水波——图像在动，牌只管往前翻，所以运动物体后面会拖一条“还在翻”的尾巴）；机场出发大屏那样的一行行字，目的地一列列刷新；倒计时 / 翻页钟（设计师今天最常用的就是这个）；从一个点扩散开的涟漪。结尾：一道波扫回「翻牌 SPLIT-FLAP」，底下一行小字翻出“观默”，最后一块牌单独落定。

**设计师能拿走的数**（标在画面上）：一张牌的时间（约 67 ms）、重力缓动而不是 ease-out、回弹 4%、延迟 = 距离 × k、卡片的顺序决定路过什么、中缝 2 px、下半张上的影子。

**渲染建议**：牌很多但每块只有三个四边形（上半张、下半张、正在掉的那张），WebGL 实例化或 Canvas 2D 都够快；要带透视（推到特写要连续）。每块牌的状态 = f(帧号, 这块牌的日程表)，纯函数。快的牌要有运动模糊（子帧累加）。配色：哑光黑 `#141414`、牌面米白字 `#F2EDE3`、信号黄 `#FFD400`、少量机场红 `#E8392B`；顶上一排灯，牌面有很弱的反光和卡片边缘的磨损。

**配乐**：机械、干、有律动——“嗒”声本身就是打击乐（波扫过 = 一串十六分音符），加一个原声贝斯和颤音琴；不要铺底的大合成器。

**风险**：中文在点阵里要够大才认得出（「翻牌」每个字至少 20 × 20 块）；整面墙同时翻的时候画面会“花”，H.264 会糊——那几帧核对一下成片解码出来的样子。
