# 湿拓 Marbling · 制作过程

## 第二版（2026-11-14）：七个场景，一台 3D 镜头连续走

主人看第一版：“动效可以做到顶尖一点，而且我希望至少有 3 个或者 4 个以上场景切换，你这只有一个太枯燥了。我要做推特爆款。”

成片：`film/marbling-film.mp4`（18 秒，1080 帧，1920×1080，60fps，24.7 MB，响度 -14.2 LUFS）。重出：`bash film/make.sh`。分镜见 `film/STORYBOARD.md`。

- 第 0 帧没动（第一版已过 `cover.py` 的那一帧：俯视梳到一半）。
- 平面换成真的 3D：镜头 [x, z, 缩放, 横滚, 俯仰, 高度]，FOV 34°，每个像素从镜头打一根射线到水面（Y=0），再走原来那套倒查。正俯视时和第一版的 2D 映射完全一样。加了两只盘、盘沿、胡桃木桌、柔光箱反射（Schlick 菲涅耳）、远处的雾、水面里的蛋倒影。
- 七个场景：① 俯视·梳 → ② 放倒到 27° 的低机位 → 横甩 3600 px 到 B 盘 → ③ 低机位·滴（珠子 3D 重力下落、拖影、影子收拢）→ 升回俯视 → ④ 耙、梳 → ⑤ 卷 + 推进 ×21 → ⑥ 斜 34°·浸蛋 → ⑦ 成品（蛋在灯下转、签条、署名）。镜头关键帧是 Hermite（邻点斜率），缩放在对数空间插值。
- 新动作“浸”（`marble.js` 的第 4 种动作）：蛋沉到 y，吃掉 πρ₀² 的膜，四周 |P′−C|² = |P−C|² − ρ₀² 往里流；蛋上一点 = 水面上半径 ρ₀ = √(2a(y+b)) 那一圈（阿基米德球带面积，面积对得上）。蛋落的位置就是 ×21 推进去的那一处。
- 快镜头（甩、升、推进）带运动模糊：屏幕速度 > 45 px/帧时，在 0.5 帧快门里取最多 5 个镜头叠到画布上，叠的样本只用 1 个采样。

### 一帧多少秒

全质量 1080 帧共 4937 s（82 分钟），平均 4.57 s/帧；俯视那几段约 3.9 s，带运动模糊和蛋的那几段约 4.9 s（累计平均在第 880 帧最高到 4.93）。预览（半分辨率、隔一帧）约 1 s/帧。

第一次 11 Mbps 编出来 25.9 MB，超了，降到 10.5 Mbps 重编（数字几乎没变）。最大差 36.4 在第 778 帧：×18 推进里又粗又对比强的条纹在转，不是跳变。从成片解码看过第 135（甩）、778（×18）、925（提蛋）、1040（成品）帧：条纹边缘锐、没有明显的压缩块，蛋上的羽纹清楚。

### 最没把握的 2 秒

**1.9—2.6 秒的横甩 + 刚到 B 盘**：从满屏颜色甩到一盘清水，到第一滴落下前约 0.2 秒画面是一大片奶油色的空盘。静帧看运动模糊是连续的，但播放时甩得爽不爽、空盘会不会让人划走，要主人看。

### 没做 / 没验证的

- Claude 看不了播放、听不了声音：看过的是联系表（每 30 帧）、预览全片的连续帧和上面几张全质量解码帧；配乐只核对了时长和响度。
- 第 925 帧前后，“浸”的标注线从字块斜着穿过蛋身（标注锚在蛋右侧的水面上），小瑕疵，没改。
- 片尾成品段蛋下方水面上那个清水洞有一半在画面外。
- 没做风格图和指南；没加 `drafts/_lib/` 的新共用工具（`render.cjs`、`events.cjs` 仍是带 `executablePath` 的副本）。

## 第一版（先导片，2026-11-13）

成片：`film/marbling-film.mp4`（16 秒，1920×1080，60fps）。一条命令重出：`bash film/make.sh`。分镜和第 0 帧见 `film/STORYBOARD.md`。

## 只做了一件事：颜色不混，只互相推开

整片没有一帧是“画”出来的：每个像素都把动作表（滴 / 耙 / 梳 / 卷）从后往前逆变换回去，看它落进哪一滴（`film/marble.js`）。所以：

- 每个动作都精确保面积。r ∝ √t 不是缓动，是“面积匀速流出”的结果。
- 同一圆心连滴 n 滴的复合逆变换也是闭式（减去总面积），一个靶心只算一次，一整盘 100 多滴只占 20 多个动作。
- 梳 / 耙的位移有前沿：齿尖前面 L2 内递减，用“目标坐标”写位移，逆变换就是显式的，正变换不折叠（要求 L0 > 1.5z）。
- 推进 ×21 时边缘还是锐的，因为根本没有纹理，只有公式。推进的落点是用 JS 版的同一套倒查在全盘搜出来的（96×54 px 的窗里颜色变化最多的一处），第一版落在一片空白奶油色上。
- 纸是一张卷在半径 120 的圆柱上的矩形纸：揭起来的部分翻过来平压在没揭的那一截上，背面 = 印下来的画（镜像）。开头从左上角斜着揭，结尾横着翻、镜头跟着翻页甩过去。

## 一帧多少秒（云端 4 核，SwiftShader）

| 做法 | 第 0 帧（约 90 个动作） |
|---|---|
| 1 个采样 | 3.9 s |
| 整屏 4× 超采样 | 14.8 s |
| 同一个程序里写自适应抗锯齿（shade() 被内联 5 次） | 1 采样也涨到 5.4 s：SwiftShader 上着色器的体积本身就贵 |
| **两个程序：第一遍 1 采样存“碰到哪一滴”，第二遍只在和邻居不同的像素补 4 个采样** | **5.9 s** |
| 预览（半分辨率、不补采样） | 0.9—1.1 s |

固定开销约 0.7 s（空着色器也要这么久），每个动作每个采样约 18 ms。

## 审片

1. 第 0 帧单独全质量出图，看原图和宽 360 的缩略图：「湿拓」读得出，羽纹 / 梳子 / 靶子三块分得开。第一版留白太多，加大了每个靶心的面积。
2. 半分辨率全片（隔一帧）+ 每 30 帧的联系表 + `smooth.py`：0 段死区；跳变集中在三处最快的动作（揭纸、耙的三道）。耙改成来回两道、每道 60 帧，揭纸放慢到 76 帧，三处都换成正弦缓动（峰值速度是线性的 1.57 倍，inOut2 是 2 倍）。
3. 自查“哪 2 秒最平”：揭完纸以后的 2.5—4.5 秒（一个小靶心在一大片奶油色里慢慢长）。改了一轮：第一个靶心的四滴更大、更快（每 15 帧一滴），后面的靶心提前 22 帧开始，镜头提前拉回。

## 两个检查的输出（原文）

全片（960 帧）全质量约 5.0—5.5 s / 帧（第一盘动作多的帧 6 s，纸的帧 7 s），共约 85 分钟；中途容器重启过一次，从第 586 帧续渲。成片 22.7 MB。

第一遍成片 `smooth.py` 报了两处跳变，都是真的：
- 第 96 帧：盖纸 → 揭纸换模式那一帧，纸背透色从 0.74 跳到 0.8（盖纸时的透色在第 98 帧才到 0.8）；
- 第 883 帧：盖最后一张纸时，水面的动作表比揭纸早 5 帧清空，纸背透出来的颜色一下子没了。
改完只重渲了这两段的 78 帧。第二遍：

```

跳变 0 处：[]
死区 0 段：[]
```

```
第 0 帧：亮度 156 · 对比 60 · 细节 16.7　｜　全片好帧：对比 61 · 细节 16.6　｜　前 0.2 秒变化 5.12
没有低级错（不空、不弱、0.2 秒内在动、前 2 秒没停）。抓不抓人要看图、要主人看。
```

最大的 48.9 在第 803 帧：×21 的位置刚开始往回拉，条纹又粗又对比强，一点点移动就是很大的像素差，不是跳变。从成片解码了第 792 帧（×21）和第 576 帧（梳）的局部看过：边缘是锐的，×21 的条纹上有很轻的压缩块，不糊。

## 最没把握的

- **1.4—2.6 秒的纸**：盖下去以后纸背透色，整屏是一片粉彩，到揭起来那一角翻出鲜艳的印画之前，大约有半秒是全片最淡的画面。
- 推进到 ×21 时条纹又密又在转：静帧解码过不糊，但播放时会不会闪，要主人看。

## 没做 / 没验证的

- Claude 看不了播放、听不了声音。看过的是静帧、连续帧和联系表；配乐只核对了时长、响度（-14 LUFS）和每 0.5 秒的音量曲线（滴落那一阵原来比别处响 12 dB，已压平）。
- 没做风格图和指南（任务书只要片子）；没做 `drafts/_lib/` 的新共用工具。仓库装的 Playwright 1.64 和云端预装的浏览器对不上，所以 `film/render.cjs`、`film/events.cjs` 是 `_lib` 里那两个的副本，只多了 `executablePath`。
