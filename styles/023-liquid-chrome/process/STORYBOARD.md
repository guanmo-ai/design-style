# 液态金属 Liquid Chrome · 分镜（全片 18 秒 · 第三版）

1920×1080 · 60fps · 120 BPM（一拍 = 30 帧）· 1080 帧。画面 `film.html`（复用 `../chrome.js` 光线步进渲染器，新加了鸟、豆子、气球、城市环境、电影感的舞台），时间轴 `timeline.js`，配乐 `audio.py`。出片：`bash make.sh`。

**第一版的问题（主人 2026-11-06）：** “画面还可以，但比较枯燥”。和点云一样：章太长、主角是抽象的珠子，没有作品、没有“搭”的过程。

**第二版：** 每章 3 拍一件真实的镜面雕塑，一章换一种金属颜色和一个世界：金（鸟）→ 洋红（气球狗）→ 黑（磁流体）→ 银 + 城市（云门）。
**第三版（主人看第二版：“这一连串的变是可以的，但是少了音效”“这个地板不好看……尽量往影视大片的方向搞”）：**
- **地板：** 棋盘格换成电影感的舞台——黑色湿石材（湿的地方像镜子、干的地方发哑，两层噪声），头顶一盏聚光灯在地上落一圈暖光，光柱是一根往下张开的体积光锥，里面飘着灰尘；背景从藏青换成深青，和暖光成“青橙”对比。开场和片尾淡入淡出（不再硬切）。都在 `../chrome.js` 的 `shaft()` 和地面分支里，`s.checker` 现在是舞台的强度 0—1。
- **文字的声音（主人 2026-11-06：“文字变得很快，但是少了音效跟它搭配”）：** 屏幕上的字不再一下子整行出现，而是从左到右“解码”（`../../_lib/typefx.js`）：前沿几个字是乱码，每落定一个字一声“嗒”（音高取当前和弦），章节标题 3 帧一个字、是键帽声，规则卡的大字先吸一口倒放镲再“砸”下来，英文和公式跟在后面解码。页面初始化时把每一帧的 HUD 空跑一遍，把所有文字出场登记成 cue，`node ../../_lib/events.cjs film.html events.json` 导出给 `audio.py`——声音和画面用同一份数字。

**签名物理：** 表面张力（先长颈再合上、合完晃三下、拉长了断成一串珠）。**接力元素：** 同一滩水银——上一件作品化掉、滴下来、塌下去，就是下一件的开头。

## 渲染上踩过的坑（给下一期）
- SwiftShader 上同一份大着色器，空背景也要 2 秒 / 帧：同一份代码编译两遍——“背景版”编译期去掉光线步进；完整版只在物体（含地面倒影）投到屏幕上的矩形里画。
- 液滴 / 液丝 / 波纹 / 气球的数据放进一张 64×14 的浮点纹理里 `texelFetch`，不要用 uniform 数组。
- 每组图元一个包围盒，整个场景一个包围盒，射线碰不到就不走。约 1—4 秒 / 帧。
