# 设计笔记：主人对短片的要求

新一期开工前先读这份。下面是做 009 新粗野主义时，主人审片给出的反馈，适用于以后每一期。

## 目标

- **推特爆款。** 设计师看了觉得真有用，动效要做到让人觉得“做得非常好”。
- **对设计师有用。** 给能直接拿走的东西：规则、数值、CSS、配色、字体，以及落到真实界面里的样子。

## 短片

1. **第一帧就要好看。** 推特静音自动播放，第一帧就是封面；0.2 秒内要有动作。首尾同一帧，配乐的余音折回开头，循环播放看不出接缝。
2. **镜头不要一直抖。** 只在少数关键落地点往下“咚”一下（单向，不来回颤）；落地弹簧的过冲控制在 5% 左右。
3. **动效要惊艳，不要“老实”。** 主人审片时说过“太老实”的反例：东西事先摆好、只有局部在动，整片像幻灯片。怎么做到惊艳，不设规则，放开发挥。

   下面只是做过、效果不错的参考，可以用、可以混搭，也鼓励完全换一种思路：
   - 元素一个个长出来、落进来；
   - 某一刻让一个巨大的主角占满画面；
   - 用同一个东西接力换章（钻进字母的孔、整张画布甩过去、一张卡撑满全屏、同一面网格变形）；
   - 镜头本身在动；
   - 给整片定一条物理规则（009 用的是“阴影长度 = 高度”）。

4. **节奏宁可慢一点，让人看得清。** 总长 15—20 秒，按内容定，不必卡死 15 秒。信息密的章节多留时间。
5. **一定要有落到网页和手机 App 里的样子。** 让设计师看到风格用在真实界面里的效果。
6. **手机上要看得清。** 代码和说明用大字，静音也能看懂，每条规则都写在画面上。

## 质量标准（014 选题时主人补充）

- **标准是最早那几期：** 001 包豪斯、002 瑞士国际主义，以及布局 01 便当盒、02 瀑布流。013 装饰艺术、欧普艺术候选只算“正常”，不当标杆。
- **要比它们做得好，但不被它们限制。** 不照搬它们的做法，只要求成片明显超过。
- **013 的教训：** 第一版只有平面上的打开 / 合上（scaleX、淡入淡出），没有纵深、没有光，被评“太普通”；第二版加了真纵深、沿线跑的光、万花筒、视差，评价“好一点，但还不算顶尖”。动效优先级不低于设计。

## 动效做到顶尖的检查表（014 第三版总结）

014 第二版被评“很普通”，原因是骨架还是幻灯片（每章同一个版式 + 甩镜翻页）、动作只有“A → B 插值 + 弹簧”、没有做只有这个风格才能做的动作。第三版按下面这张表重做，以后每一期开工前对一遍：

1. **先列这个风格“独有”的动作**（014：涟漪、焦散光池、颈与飞溅的小水珠、穿过玻璃、离墙越高影子越远），只让它们占画面；任何风格都能做的淡入、平移、缩放只做配角。
2. **每个大动作都有起势和收势**：先往反方向蓄 6—12 帧；落地过冲约 5%；液体 / 弹性的东西落地后再抖 2—3 下（抖形状，不抖位置）；附属元素晚 3—6 帧跟上。
3. **节奏要有反差**：慢—慢—啪，“啪”落在重拍上；中间留出能看清的停顿。
4. **镜头由动机驱动**：跟着主角走、推进、穿过；不为换页而甩。两章之间用“同一个东西接力”（穿过它、它变成下一章的主角）。
5. **每 1.5—2 秒出现一种没见过的动作**，同一种动作不连着用两次；每章换一个场景版式。
6. **字是动效的一部分**：按行从遮罩里升起（约 16 帧 ease-out），不要淡入；主角会从字上经过、和字发生关系。
7. **运动模糊覆盖所有快动作**（不只是镜头）；换场景 / 换坐标的那一帧不跨子帧。
8. **用曲线和胶片条检查时间，不只看静帧**：`scripts/motion_curves.mjs` + `plot_curves.py` 画主角的位置、大小、速度、高度和镜头速度（查跳变、死区、过冲）；`scripts/stills_batch.mjs 起-止:步长` + `strip.py` 出连续帧胶片条（查起势、落地、节奏）。

## 渲染：网页版会话里的时长上限（014 踩过的坑）

- **网页版（云端）会话里，后台命令最长跑 2 小时，到点会被直接停掉。** 014 第三版整片一次渲染要 2 小时以上（WebGL 在 4 核 CPU 上用软件跑），渲到第 911 / 1200 帧时被停，前面将近 2 小时全部作废：Remotion 边渲边写的 mp4 要等最后一帧写完才补上文件索引（moov），中途停掉的半截文件打不开、也救不回来。
- **以后一律分段渲染：** `bash scripts/render_chunks.sh <合成> <起始帧> <结束帧> out/chunks/cN.mp4`，每段控制在 40 分钟以内（014 是 300 帧一段），一段一个后台命令，渲完一段再开下一段；全部渲完用 `bash scripts/concat_chunks.sh <音乐.wav> <输出.mp4> 段…` 无损拼接并配乐。分段之间没有接缝：每一帧都是时间的纯函数。
- **开渲之前先估时：** 先用 `scripts/stills_batch.mjs` 出几帧（含最复杂的段落）看每帧多少秒，再乘帧数、除以并发，超过 40 分钟就分段。
- **等待用后台命令 + 完成通知，不要靠一个超长的前台 / 后台等待命令**（它们同样受 2 小时上限）。

## 配乐

- **全片一个速度，不变速。** 画面要放慢只能按整拍放，后面的剪辑点仍要落在拍点上；不要让某一段的 BGM 跟着变慢。
- **音效别盖过 BGM。** 一段里音效太密时先降音量或删掉一部分（009 的 4—5 秒出过这个问题，已在 day-09-audio-v2 调小音效）。

## 流程

- **先出候选。** 先给三个候选风格，各做三张图（海报、速查卡、App 概念），每个附一段动效设想的文字；主人选定后再做全套。没选上的放进 `drafts/`，留着以后做。
- **候选阶段只出图，不做动效样片。** 主人会经常让做新风格，样片太费 token；动效留到选定后在正片里做。
- **先看前几期。** 新一期的完成度要超过 001 包豪斯、002 瑞士、布局 01 便当盒、02 瀑布流（见上面的“质量标准”）。拿不准时下载它们的 Release 成片逐帧对比。
- **分工。** Claude 只做设计（选题、风格图、画面、配乐）；工程、发布、部署交给 Codex，写进 `docs/HANDOFF.md`。
