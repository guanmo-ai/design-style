# 设计笔记：主人对短片的要求

## 先读这一段：哪些必须守，哪些只是参考（2026-11-11 整理）

主人看完毛绒那一期：“效果挺不错的，动效很顶尖、很丝滑”“不要让仓库限制了你以后的发挥”“（制作过程）只是给后面的人参考，不会限制后面的人发挥”。

这份文档是按时间一条条攒起来的审片反馈。攒久了，每一条都像必做项，连着几期的片子长成了同一副骨架（开场 → 代表作 → 五条规则 → 手机 → 片尾）。从现在起分三层读。**分层和下面八条是 Claude 从历次反馈里挑出来的，不是主人逐条定的——主人随时可以增删。**

**第一层 · 必须守（只有这八条）**

1. 目标的排序：**X 爆款 → 动效顶尖 → 对设计师真的有帮助**。动效的底线是毛绒那一期（主人 2026-11-11：“以后至少达到这样的标准”“我更希望它能丝滑一点，动效做得顶尖一点，让人有惊艳的感觉”；每个类型要求可以不一样，但不能比它糙）。怎么对照，见下面“丝滑是怎么来的”。
2. **第 0 帧就是封面，要让人停下来点赞、收藏、评论，并且开工时先单独交给主人看**（主人 2026-11-13：“我们的第一个画面是要吸引人的……以后我让你做新视频的时候，你记得一定要给我第一个画面”）。X 静音自动播放，0.2 秒内有动作。
   - 做新片的第一件交付物是第 0 帧（最好 2—3 个方向并排），主人选定后再做全片；改片子时第 0 帧也要重新看一遍。
   - 判断标准是“缩到手机信息流里那么小，还想不想点开”：一个大主角、强对比、一眼看出“这是怎么做出来的？”（做到一半 / 前后对比 / 一张图里很多样东西），字少而大。只有一行大字的海报不够（马克笔 v4 的第 0 帧被评“一般”）。
3. 手机上看得清，静音也看得懂。
4. 设计师看完能拿走东西：数值、规则、颜色，或者这个风格实际用起来的样子。用在哪由风格决定——海报、插画、封面、视频、图片、界面都行。**网页和手机 App 只是推荐，不强制**（主人 2026-11-11：“有些是适合网页和手机 APP 的，可以做上，只是推荐，不强制”“后面可以做视频，也可以做图片”）。放在哪、占多长、用什么形式，自己定。
5. **BGM 和音效必须做好，和画面同等重要**（主人 2026-11-13：“在这个项目一定要限制好，BGM 音效要做好……不影响 Claude 的发挥，但是强调一定要把 BGM 和音效做好”）。底线：
   - BGM 是**一整首歌**：有鼓（律动）、有贝斯、有一条记得住的旋律，按拍子换和弦；全片一个速度，换章只换和弦不换乐队。只有铺底和弦、没有鼓和旋律的不算（沙画第一版被评“非常差”）。
   - **画面上每个大动作都有一个声音，并且落在拍点上**；屏幕上每次出字都有声音。音色跟着这一期的材料走（毛绒是软的噗 / 啵，马克笔是笔头擦纸、拔帽、扣帽）。
   - **不能有噪音感**：不要用一长段宽带噪声当“质感声”，几十段噪声叠在一起就是噪音（沙画第一版的教训）；材料的摩擦声要短、要调过音、压在配乐下面。
   - 音效不盖过配乐；母带 −14 LUFS 左右、不削波。
   - **鼓停 = 观众觉得片子停了。** 马克笔 v3 第 5 秒笔停在鞋头上积墨 24 帧、同时鼓停，画面其实一直在动（镜头在推），主人仍然说“好像有停顿”；`smooth.py` 量不出来。想强调一个瞬间，用音色变化（加一个和弦、一声铃），别让鼓停；要停只在片尾收束前停。
   - Claude 听不见，交片时要把“每个声音在第几帧、对着哪个动作”列出来，并说清楚只核对了数字、没听过。
   - 交片前跑 `python3 drafts/_lib/audiocheck.py <成片> drafts/plush/film/plush-film.mp4`：响度、峰值、噪音感（频谱平坦度、高频占比）、律动（拍子处的自相关）、有没有断掉的空洞，和主人认可的毛绒并排看。
6. 结尾有一个真正的收束（一个动作 + 一个声音），最后一帧能看到署名“观默”。
7. 只用可免费商用的字体；不照搬某一件具体作品的造型，只提取风格。
8. 上架、发布要主人审片通过。

**第二层 · 默认骨架（好用，但可以打破）**

一章一件真实代表作、五条规则卡、固定外框（左上章节 / 右上进度）、单独一章“用在手机上”、首尾呼应、15—20 秒、先出三个候选再做全套、先验开头再做全片、每期四张风格图。它们过审最稳，想不出更好的就用；有更好的想法就换。Claude 的建议：每三期至少有一期不按这副骨架来，不然观众会认出模板。打破的时候在那一期的 `PROCESS.md` 里写一句“这次没做什么、为什么”。

**第三层 · 经验（下面全部内容，包括 [`BENCHMARKS.md`](BENCHMARKS.md)、[`GPU_MOTION.md`](GPU_MOTION.md) 和各期的 `PROCESS.md`）**

是“当时那一期为什么过 / 没过”的记录。里面写着“一定”“每一期”“必须”的句子，除了上面八条，都按“那一次的教训”理解。和眼前这一期的材料冲突时，听材料的——例如“往影视大片的方向做”说的是液态金属的黑场和聚光灯，毛绒用的是糖果色的亮背景，同样过了。

> 给下一个做片子的人：先想清楚这种材料 / 风格**自己会怎么动**，把这一条做到最好；规则卡和手机章做得平，往往是因为它们是照着清单填的。

下面是从 009 新粗野主义起，主人每次审片给出的反馈，按主题归在一起。

## 目标

- **推特爆款。** 设计师看了觉得真有用，动效要做到让人觉得“做得非常好”。
- **对设计师有用。** 给能直接拿走的东西：规则、数值、CSS、配色、字体，以及落到真实界面里的样子。

## 短片（第 1、2、6、7 条里的硬要求已收进上面八条，其余是参考）

1. **第一帧就要好看。** 推特静音自动播放，第一帧就是封面；0.2 秒内要有动作。结尾要有一个真正的收束（一个动作 + 一个声音），不要突然中断；首尾同一帧、配乐余音折回开头的无缝循环可以做，但不是必须（2026-10-29 主人：“结尾不用一定要跟首尾呼应”）。
2. **镜头不要一直抖。** 只在少数关键落地点往下“咚”一下（单向，不来回颤）；落地弹簧的过冲控制在 5% 左右。
3. **动效要惊艳，不要“老实”。** 主人审片时说过“太老实”的反例：东西事先摆好、只有局部在动，整片像幻灯片。怎么做到惊艳，不设规则，放开发挥。

   下面只是做过、效果不错的参考，可以用、可以混搭，也鼓励完全换一种思路：
   - 元素一个个长出来、落进来；
   - 某一刻让一个巨大的主角占满画面；
   - 用同一个东西接力换章（钻进字母的孔、整张画布甩过去、一张卡撑满全屏、同一面网格变形）；
   - 镜头本身在动；
   - 给整片定一条物理规则（009 用的是“阴影长度 = 高度”）。

4. **节奏宁可慢一点，让人看得清。** 总长 15—20 秒，按内容定，不必卡死 15 秒。信息密的章节多留时间。
5. **推荐（不强制）：落到网页和手机 App 里的样子。** 让设计师看到风格用在真实界面里的效果。当初写的是“一定要有”；2026-11-11 主人改为推荐——适合界面的风格可以做，不适合的换成它最自然的用法（海报、插画、封面、视频、图片）。
6. **手机上要看得清。** 代码和说明用大字，静音也能看懂，每条规则都写在画面上。
7. **结尾署名“观默”。** 每一期视频的最后都要有署名“观默”（2026-10-29 主人定，从 018 起）：放在片尾片名下方或角落，跟这一期的字体和配色走，最后一帧还能看到；首尾循环的片子，署名在倒放 / 接回开头之前出现。
8. **能选的时候，往影视大片的方向做。** （2026-11-06 主人：“我们整个项目，如果你有的选的话，那你尽量往影视大片的方向搞”）布景、光、镜头都按电影来：黑场里的一盏顶光和光柱、湿地面的倒影、体积雾和灰尘、青橙对比、镜头滑过去而不是硬切。反例：液态金属第二版的棋盘格地面（“不好看”），第三版换成黑色湿石材舞台 + 聚光灯后才过关。

## 质量标准（主人定的排序 · 参考）

- **最高水平是 003 构成主义 Constructivism**，其次 004 孟菲斯 Memphis；001 包豪斯 Bauhaus、布局 02 瀑布流 Masonry、005 波普艺术 Pop Art 都不错。新一期的完成度要对标它们。它们为什么好，已经拆解在 [`BENCHMARKS.md`](BENCHMARKS.md)：开工前读这份文档就够了，不用再下载成片逐帧看。
- **最近通过、主人明确说好的**：022 点云、023 液态金属（2026-11-06：“这一次效果都不错”）、毛绒草稿（2026-11-10：“动效很顶尖、很丝滑，这种感觉我很喜欢”，过程见 [`drafts/plush/PROCESS.md`](../drafts/plush/PROCESS.md)）。这几期的共同点：先定一条真的物理规律，再让同一批东西从头接力到尾。
- **要比它们做得好，但不被它们限制。** 不照搬它们的做法，只要求成片明显超过。
- 013 装饰艺术、欧普艺术候选只算“正常”，不当标杆；014 液态玻璃的价值在流程和工具（检查表、曲线、胶片条、草稿预览、显卡渲染分工），不是质量标杆。
- **013 的教训：** 第一版只有平面上的打开 / 合上（scaleX、淡入淡出），没有纵深、没有光，被评“太普通”；第二版加了真纵深、沿线跑的光、万花筒、视差，评价“好一点，但还不算顶尖”。动效优先级不低于设计。

## 丝滑是怎么来的（毛绒复盘 · 底线怎么对照）

主人说的“丝滑”“惊艳”是看播放的感受，Claude 看不了播放，所以把它拆成能做、能量的几件事。毛绒那一期做到了这些：

1. **没有硬切。** 全片是同一批东西接力到底，换章是它们飞过去，背景色、光、镜头在同一段时间里一起渐变。
2. **位置连续，速度也连续。** 身体的动作用弹簧和缓动，镜头的推拉按等比走；任何一个参数都不在某一帧突然换值——包括看不见的开关（毛绒第一版在“地面换成墙”那一帧整屏跳亮了一下，静帧完全看不出来）。
3. **动的东西身上总有更慢的东西。** 身体停了，毛晚 5 帧到、冲过头、抖回来。跟随和过冲是算出来的（姿态历史 ⊗ 弹簧响应），不是一个个 K 的，所以每一处都有。
4. **大动作有起势和收势**，速度最快的一刻落在拍点上。
5. **60fps、细节足够密**，一帧里有东西可看。
6. **先定“这种材料自己怎么动”，再想别的。** 惊艳来自这一条，不来自清单。

交片之前量一遍：`python3 drafts/_lib/smooth.py <成片.mp4>`。它逐帧量画面变化，列出**跳变**（某一帧突然变了很多）和**死区**（停住不动超过 0.4 秒）。跳变要逐个核对是不是有意的重拍；毛绒修完之后是 0 段死区、最大单帧变化 19（修之前有两帧 44 和 61，都是没注意到的整屏亮度跳变）。它只能量“有没有不连续”，量不出好不好看——**惊艳不惊艳，最后要主人看。**

## 动效做到顶尖的检查表（014 第三版总结 · 参考）

014 第二版被评“很普通”，原因是骨架还是幻灯片（每章同一个版式 + 甩镜翻页）、动作只有“A → B 插值 + 弹簧”、没有做只有这个风格才能做的动作。第三版按下面这张表重做，以后每一期开工前对一遍：

1. **先列这个风格“独有”的动作**（014：涟漪、焦散光池、颈与飞溅的小水珠、穿过玻璃、离墙越高影子越远），只让它们占画面；任何风格都能做的淡入、平移、缩放只做配角。
2. **每个大动作都有起势和收势**：先往反方向蓄 6—12 帧；落地过冲约 5%；液体 / 弹性的东西落地后再抖 2—3 下（抖形状，不抖位置）；附属元素晚 3—6 帧跟上。
3. **节奏要有反差**：慢—慢—啪，“啪”落在重拍上；中间留出能看清的停顿。
4. **镜头由动机驱动**：跟着主角走、推进、穿过；不为换页而甩。两章之间用“同一个东西接力”（穿过它、它变成下一章的主角）。
5. **每 1.5—2 秒出现一种没见过的动作**，同一种动作不连着用两次；每章换一个场景版式。
6. **字是动效的一部分**：按行从遮罩里升起（约 16 帧 ease-out），不要淡入；主角会从字上经过、和字发生关系。
7. **运动模糊覆盖所有快动作**（不只是镜头）；换场景 / 换坐标的那一帧不跨子帧。
8. **用曲线和胶片条检查时间，不只看静帧**：`scripts/motion_curves.mjs` + `plot_curves.py` 画主角的位置、大小、速度、高度和镜头速度（查跳变、死区、过冲）；`scripts/stills_batch.mjs 起-止:步长` + `strip.py` 出连续帧胶片条（查起势、落地、节奏）。

## 高效流程：Claude 设计 + 审片，Codex 用 Mac 的显卡渲染正片（014 之后执行）

014 第三版前后花了约 8 小时，其中约 5 小时在渲染、约 2.5 小时白费。原因是云端会话的机器只有 4 核 CPU、没有显卡，WebGL 着色器全靠软件模拟，一帧要好几秒；同样的着色器在有显卡的机器上一帧几十毫秒。Codex 跑在 Mac Pro（M5）上，有显卡。以后按下面分工，**一期短片的渲染等待控制在 30 分钟以内**：

| 步 | 谁 | 做什么 | 时间预算 |
|:-:|---|---|---|
| 1 | Claude | 分镜、代码；每改一轮只出关键帧静帧（`scripts/stills_batch.mjs`）和剧本曲线（`motion_curves.mjs` + `plot_curves.py`），查构图、跳变、死区、过冲 | 每轮几分钟 |
| 2 | Claude | 动作要看连续性时，只出那一段的胶片条（`stills_batch.mjs 起-止:步长` + `strip.py`），不渲整片 | 每段 2—5 分钟 |
| 3 | Claude | 需要看整体节奏时，渲**草稿预览**：30fps、内部半分辨率、不做运动模糊（`npm run preview:NNN`，合成 `SNNN-…-Preview`） | 实测 014 约 10 分钟（正片在同一台机器上约 2 小时 20 分钟） |
| 4 | Codex | 关键帧和预览都过了，才渲**正片**：在 Mac 上 `npm run render:NNN:gpu`（`--gl=angle` 走显卡），把成片推到 `review-renders` 分支的 `NNN/` 目录 | 几分钟 |
| 5 | Claude | 拉下成片审片：首尾接缝、每段抽帧联系表、关键动作连续帧、字幕、和预览对比有没有显卡与软件渲染的差异；有问题改代码，回到第 4 步 | 每轮十几分钟 |
| 6 | 主人 | 看成片，提意见或通过；通过后 Codex 发布 Release、上架画廊 | — |

- **用到 WebGL / 着色器的期，Claude 不在云端渲正片**，交给 Codex 用显卡渲（除非 Codex 不可用；那样就分段渲，见下一节）。
- **纯 SVG / Canvas 2D 的期（015 起），Claude 直接在云端渲正片**：不需要显卡，015 整片约十几分钟；渲染在后台跑，几乎不花 token，省掉交接、Codex 读说明、推上来再拉下来这一来一回。Codex 只负责审片通过后的发布。动笔前先想清楚能不能不用 WebGL。
- **Codex 只执行渲染，不改设计。** 渲染报错或画面和预览不一致，把现象和截图记进 `docs/HANDOFF.md`，由 Claude 修代码。
- 每期新短片都要提供三条命令：`render:NNN`（云端软件渲染，兜底）、`render:NNN:gpu`（Mac 显卡）、`preview:NNN`（草稿预览）；合成里留 `step` / `blur` / `res` 参数，预览合成用 30fps、`step: 2`、`blur: 1`、`res: 0.5`。注意：Remotion 的 `--scale` 只缩小最后的截图，着色器和画布要靠 `res` 真的按小尺寸算才会快。

## 开头 7 秒（015 第二版主人反馈 · 参考）

第一版 015 被评“前 7 秒不够吸引人、节奏一般、没有轻松的感觉，看上去无感”。改版后的结论：

- **第 0 帧放在全片能量最高的那一刻**（015：赛车正撕开横幅），不要从“进场 → 停住”开始；前 2 秒不能有静止的停顿。
- **往电影感靠，但只靠光影和剪辑，不拍剧情片**：光（车头灯、路灯光锥、聚光灯、高光、倒影）、纵深（低机位、多层视差）、剪辑（匹配剪辑、物体擦过镜头转场、慢动作接追回）。不要遮幅黑边、不要台词。
- （可选）**主角要大、要亮**：小主角放在大片米色纸上容易无感。
- （可选）**“轻松”可以来自配乐和可爱的小动作**：律动明快的大调配乐 + 落地点准的音效（字母落地一声一个音），比工业噪声好；给主角加一个有起承转合的小动作（狗急刹闻杆子 → 被拽 → 小碎步追）。
- **先验开头，再做全片**：前 7 秒最影响观感，先只做开头的关键帧和一段 5 秒预览给主人看，过了再做后面。

## 复用：每一期都站在前几期的肩上（参考）

- **先复用标杆里好的做法**：最高是 003 构成主义，其次 004 孟菲斯；001 包豪斯、布局 02 瀑布流、005 波普也不错。它们好在哪、哪些能直接拿来用，写在 [`BENCHMARKS.md`](BENCHMARKS.md)。
- **每一期都要留下可复用的东西**：动作基本件、排字工具、外框、运动模糊、配乐乐器、检查脚本……做完一期，把通用的部分抽到共用的地方（`src/lib/` 或 `scripts/`），在这里记一笔，下一期直接用。
- **代码解耦**：风格专属的画面留在 `styles/NNN-name/video/`，通用的部件不要写死在某一期里。先从标杆几期（003 → 004 → 001 / 布局 02 / 005）抽，部件清单、调用示例和新一期起步命令见 [`REUSE.md`](REUSE.md)，工程核验见 [执行记录](reviews/REUSE_20261028.md)。

## 省 token 的做法（015 复盘）

015 的 token 主要花在四处：①第一版前 7 秒整段推倒重做；②看图——每张胶片条 / 联系表都留在上下文里，后面每一轮都要带着它们；③整文件重写（Write 几百行）；④为了一个位置对不上反复算坐标、出图。以后：

1. **先验开头再铺开**（见上一节）：最贵的浪费是做完整片才发现方向不对。
2. **少看大图**：胶片条用 320px 宽、一次 8—12 帧；先用数字检查（`node out/probe.mjs` 一类脚本打印位置 / 速度，或 `scripts/motion_curves.mjs` 的曲线），确定有问题再出图；全分辨率只看最可疑的那一帧。
3. **改代码用小块编辑**，不整文件重写；一个文件超过 300 行就拆。
4. **位置对不上时直接打印数值**，不要在脑子里算——015 推近鞋子那一处靠打印两行数就找到了原因。
5. **一个会话只做一个阶段**：设计 + 第一版、改版、审片发布各开一个会话，交接写进 `PROCESS.md` / `HANDOFF.md`。会话越长，每一轮带的上下文越多。
6. **能不用 WebGL 就不用**：SVG / Canvas 2D 的整片草稿预览约 1 分钟、正片约十几分钟，可以在云端直接渲。
7. **踩过的坑**：云端下字体用 `raw.githubusercontent.com`（`github.com/.../raw` 会 403）；`build_images.py` 转 PNG 要 `CHROMIUM_PATH=/opt/pw-browsers/chromium`；运动模糊多层叠加时 SVG 的 `clipPath` id 会串，遮罩一律用嵌套 `<svg overflow="hidden">`；跟拍镜头里的残影要在“镜头里”取样（否则整个主角都拖影）。

## 渲染：网页版会话里的时长上限（014 踩过的坑）

- **网页版（云端）会话里，后台命令最长跑 2 小时，到点会被直接停掉。** 014 第三版整片一次渲染要 2 小时以上（WebGL 在 4 核 CPU 上用软件跑），渲到第 911 / 1200 帧时被停，前面将近 2 小时全部作废：Remotion 边渲边写的 mp4 要等最后一帧写完才补上文件索引（moov），中途停掉的半截文件打不开、也救不回来。
- **以后一律分段渲染：** `bash scripts/render_chunks.sh <合成> <起始帧> <结束帧> out/chunks/cN.mp4`，每段控制在 40 分钟以内（014 是 300 帧一段），一段一个后台命令，渲完一段再开下一段；全部渲完用 `bash scripts/concat_chunks.sh <音乐.wav> <输出.mp4> 段…` 无损拼接并配乐。分段之间没有接缝：每一帧都是时间的纯函数。
- **开渲之前先估时：** 先用 `scripts/stills_batch.mjs` 出几帧（含最复杂的段落）看每帧多少秒，再乘帧数、除以并发，超过 40 分钟就分段。
- **等待用后台命令 + 完成通知，不要靠一个超长的前台 / 后台等待命令**（它们同样受 2 小时上限）。

## 配乐

- **全片一个速度，不变速。** 画面要放慢只能按整拍放，后面的剪辑点仍要落在拍点上；不要让某一段的 BGM 跟着变慢。
- **屏幕上每一次出字都要有声音。** （2026-11-06 主人：“文字变得很快，但是少了音效跟它搭配”）字从左到右解码、每落定一个字一声“嗒”，标题是键帽声，大字卡先吸一口倒放镲再砸下来。做法见 `drafts/_lib/typefx.js`（画面）+ `drafts/_lib/song.py` 的 `text_cues`（声音），cue 由页面空跑 HUD 导出，声音和画面用同一份数字。“嗒”压在拍子下面（峰值比底鼓低 5 dB 左右）。
- **音效别盖过 BGM。** 一段里音效太密时先降音量或删掉一部分（009 的 4—5 秒出过这个问题，已在 day-09-audio-v2 调小音效）。
