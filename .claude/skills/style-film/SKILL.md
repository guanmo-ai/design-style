# 做一期风格短片

目标按顺序：**X 爆款 → 动效顶尖 → 对设计师真的有帮助**。动效的底线是毛绒那一期（`drafts/plush/film/plush-film.mp4`）：丝滑，让人惊艳。必须守的只有 `docs/DESIGN_NOTES.md` 开头的八条，其余文档都是参考。

这份是做法，不是清单。哪一步不适合这一期就跳过，并在交付时说一句为什么。

## 1 · 先想三件事（写进 STORYBOARD.md 开头，再写代码）

1. **这种材料 / 风格自己会怎么动？** 只属于它的那一种运动（毛绒：身体停了毛还没停）。全片的物理只围着这一条。想不出来就先告诉主人，不要套骨架硬做。
2. **什么东西从头接力到尾？** 同一批粒子、同一张纸、同一条线……换章是它变过去，不是切过去。
3. **设计师能拿走什么？** 能写成数的几件事（颜色、比例、频率、时长）。

默认骨架（代表作 / 规则卡 / 手机章）好用但会让每期长得一样。最好的段落通常是第 1、2 条直接推出来的。

## 2 · 起架子

```bash
node drafts/_lib/kit/new_film.mjs <英文短名> "<标题>"
```

组件和“换一种风格要换什么”见 `drafts/_lib/kit/README.md`。同类材料（很多根细东西）用 `drafts/_lib/fur/fur.js`；别的材料自己写渲染器，插在舞台的 `begin` 和 `end` 之间；平面风格不用舞台。

环境：`npm run fonts`、`pip install -r requirements.txt`。Playwright 和 Chromium 已经装好。

## 3 · 先测速，再定画质

云端 4 核、没有显卡。新渲染器先做一个最小页面量一帧多少秒，再乘总帧数；后台命令最长 2 小时。慢的时候每次只改一个变量再量（SwiftShader 的坑在 `docs/GPU_MOTION.md`）。

## 4 · 审片，从便宜到贵

1. 低密度全片联系表（每 15 帧一张，画质降到几分之一）：看节奏、构图、有没有空的段落。
2. 关键动作的连续帧（每 2—4 帧一张）：看起势、过冲、附属物有没有跟上。
3. 全质量单帧：看质感、字有没有压到东西。**第 0 帧是封面，单独看。**
4. 才渲正片（后台），同时写配乐和文档。

```bash
python3 drafts/_lib/contact.py <帧目录> <out.jpg> 8 400
```

## 5 · 交片前

```bash
python3 drafts/_lib/smooth.py <成片.mp4>
```

逐个核对它列出的跳变是不是有意的重拍；不应该有死区。任何 `if (进度 > 某个数)` 切换画法的地方都是潜在的硬切（毛绒第一版就有两帧整屏跳亮，静帧看不出来）。再从成片里解码一两帧，确认压缩没把细节压糊。

## 6 · 交付时说清楚

- 看过的是静帧和连续帧，不是播放；配乐只核对了时长、响度和音量曲线，没听过。
- 哪些没做、哪些没验证。
- 成片放 `drafts/<短名>/film/`，推到分支；上架、发布要主人审片通过。
- 过程记在 `drafts/<短名>/PROCESS.md`（可以照 `drafts/plush/PROCESS.md` 的样子，但它是记录不是规则）。做出了以后还能用的东西，拆进 `drafts/_lib/`。
